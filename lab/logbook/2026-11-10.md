## What was read before deciding

- **On 8.x (read-only, non-secret fields picked by name):**
  - `government.identity_frontdesk`: the motherbee and worker1 name `SY.frontdesk.gov@motherbee`;
    ingress1 and egress1 name none, and no IO node runs on either.
  - The egress: the motherbee declares `gateway_ip` 10.10.10.40; worker1 has no `egress` section,
    and its default route is 10.10.10.1.
  - No hive sets `ORCH_DEFAULT_TENANT_ID`; no WF unit runs `/usr/bin/wf-generic`; no AI node's
    config holds `behavior.capabilities`.
- **The frontdesk's name in the code (hive-config-update-v1 §2):** the router and SY.identity read
  it, and the join writes it. On a worker it is the only key that names the motherbee, since its
  uplinks are addresses. Moving it into the code touches three binaries and needs the motherbee's
  hive found at run time, for a value that never changes in an installation. Proposed: it stays
  in hive.yaml as the hive's own, and the doc's table is corrected.
- **A WAN session's traffic:** every router sends its LSA to each WAN peer every hello interval
  (10 s, `lsa_broadcast_loop`), so a session with no frame for the dead interval (40 s) is dead.
  That makes A-207's fix safe.
