## Block 3: A-138's design chat

- **The operator's frame:** a trace where each node notes what it did, the source and the
  destination above all, and nothing descriptive. It goes to the log so everyone sees it.
- **Compressing it** (zip or tar as a binary inside the JSON) was weighed first, by the numbers and
  without a run.
  - Both SDKs have the tools, and a few KB take microseconds.
  - But a cycle is a few hundred bytes, compressed bytes travel as base64, and the log would turn
    unreadable. The operator: *"no comprimir"*.
- **The id:** `trace_id` is already the cycle's id in the code.
  - An IO mints it, a reply keeps it, a WF's transition keeps its event's, and a timer's fire mints
    a new one.
  - `thread_id` is the conversation. The operator: *"trace_id es lo correcto, para esto estaba"*.
- **The operator's decisions:**
  - the trace lives one cycle, a pulse;
  - each node writes its own entry, the WF included;
  - the router writes one only when it changes the destination, which in the code is a message
    with no destination;
  - no check, no signatures, no cap, since it is for debug and log;
  - it lives in `meta.context.trace`, as solution data, not system data;
  - each entry carries the time;
  - the AI model reads it, and Archi shows it later from storage.
- **Consolidated** in [message-trace-v1](../../docs/message-trace-v1.md). Open: whether the WF's
  trail goes, and each node's `act`.
