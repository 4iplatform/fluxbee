# 2026-10-27 — Consolidating the agents' tools: the inventory, the criterion, iteration 1 (0.1.87)

Where the track stands is in [agent-tools-v1](../../docs/agent-tools-v1.md) §5–§6; the facts of the
release are in the ledger's [0.1.87 entry](../DEPLOYMENTS.md).

## How it went

- **The inventory (§5):** every model tool in the code, by owner:
  - ai.generic;
  - the frontdesk;
  - Archi's 19;
  - SY.admin's executor;
  - the services that could become base tools.
- **The operator's criterion:**
  - only ai.generic gets an ordered toolbox: *"este nodo es el porqué pensamos en esto ordenado"*;
  - the frontdesk, Archi and the executor keep their specific tools;
  - the mechanism is shared, and the toolboxes are not;
  - the overlaps get aligned. Checked: both `get_admin_action_help` tools call the same SY.admin
    action, so they were only named alike.
- **Iteration 2's rules (§6.2), decided in one exchange:**
  - `read_blob` reads the whole hive for now;
  - reminders are for the agent itself;
  - `send_message` sends to a destination in the agent's own tenant;
  - unpublish is in;
  - `update_html_page` stays pending. A link is content-addressed, so an update means publishing
    again.
- **Iteration 1 (0.1.87):**
  - one agent built it; one review caught Archi's PROD cookbooks still teaching `gpt-5.5`, and a
    published link that could be lost;
  - both were fixed: seeds versioned and replaced once with a log line, and the link appended to
    the reply.
- **The gate found A-109.** `AI.pruebas` was still answering with the 0.1.86 tools, because a node
  that follows `current` moves only when its orchestrator starts, and this release did not change
  the orchestrator. `restart_node` moved it, and `node_help` then showed the stale version
  (A-101).
