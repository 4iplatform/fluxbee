## 14:53–15:16 — fb-build's qga stuck: diagnosis and root cause
- **Environment:** prod · **Type:** read-only + reversible (2 reboots, 3 resets of fb-build)
- **Symptom:** after an `exec` the agent stopped answering (even `ping`), and after each
  reboot/reset it answered `ping` but got stuck again on the first `exec`.
- **Hypotheses ruled out with evidence:** load (host cpu 0 %, VM idle); full disk (`/` at
  34 %, via `agent/get-fsinfo`); new kernel (the reboot did activate **6.8.0-142**, but `exec` of
  `true`/`uname`/`bash -lc` work on it); non-ASCII characters in general (`é` goes through).
- **Root cause (controlled A/B):** `exec` with `—` (U+2014) → `guest-exec failed - got timeout`
  and the agent stays dead until restarted; with `é` (U+00E9, Latin-1) nothing happens. The `exec`s
  that got it stuck today had `—`. → FINDINGS B-11.
- **Fix:** `lab/pve.py` — non-ASCII argv travels in base64 and an ASCII bootstrap decodes it in the
  guest; also, the output's mojibake is undone and `HOME` is set (the B-7 solution, which had not
  been applied). Validated live: accents/`—`/`✓`, exit codes, and the agent survives.
- **Observation:** every PROD VM has a pending reboot (kernels 6.8.0-137…142 + libc6,
  installed by `unattended-upgrades`). fb-build already runs 142 with no problems. → FINDINGS B-12.
- **Status:** OK · **Rollback:** N/A

## Operator decisions

1. **Repo IP: it stays DHCP.** The router keeps the assignment as long as the MAC does not change
   (`BC:24:11:EF:96:80` → `192.168.8.180`); it is neither reserved nor fixed. *(It departs from the
   general guidance in `docs/packaging-and-build.md` §4.3 by explicit decision.)* Derived rule: **do not
   recreate `net1`** (another MAC → another IP). Noted in the HANDBOOK.
2. **fb-build stays always on** (it serves the repo to the devs). HANDBOOK updated.
3. **Commit, with a new convention:** every commit references the current fluxbee version in the
   subject (`[0.1.33] …`), the body references the changes, and every install changes the version.
   It was not written down → added to HANDBOOK §12 ("Commits and versions").
4. **No GPG signing** of the repo: it stays `[trusted=yes]`.
5. **The agent runs the infra** ("hacé lo que creas conveniente — no hay nadie usando PROD,
   estamos en piloto alfa" ("do whatever you think is best — nobody is using PROD, we are in an
   alpha pilot")) → the pending B-12 reboots are applied (next entries).
6. **Snapshots: never more than 3 per VM** ("borrá los snapshots viejos inútiles, no más de 3 nunca,
   ponelo en el handbook" ("delete the useless old snapshots, never more than 3, put it in the
   handbook")) → the 18:09 cleanup and HANDBOOK §12.
