# 2026-10-28 — Iteration 2 shipped (0.1.89); the WF track opened, and its Case 0 decided

Where the tracks stand is in [agent-tools-v1](../../docs/agent-tools-v1.md) §6.2–§6.3 and
[wf-orchestration-v1](../../docs/wf-orchestration-v1.md). The release's facts are in the ledger's
[0.1.89 entry](../DEPLOYMENTS.md).

## How it went

- **The operator turned iteration 2 around (2026-10-27, evening):**
  - OPA is for rules of substance, not for routing between nodes (A-113): *"una enredadera de
    reglas OPA imposible de debug"*;
  - the AI node stays a pure responder. It has two kinds of event: a message to answer, and a
    timer, which lives in a WF;
  - reminders and `send_message`, already built, left the node.
- **The WF is *"la interconexión inevitable determinística"*:**
  - it forwards a message as it received it;
  - it may change the destination, and some content through CEL;
  - it routes by node names written in its definition. A person enters and leaves only through an
    IO node, and the ILK travels intact.
- **The WF review** (wf-orchestration-v1) set out:
  - what works;
  - what is broken: A-117 (dead timeouts, and a send to an agent hangs), A-118 (the engine's
    robustness), A-119 (open control verbs);
  - the cases to take one by one.
- **Case 0 decided (§5.1).** The operator accepted the seven proposals:
  1. a WF always sends `user`. In principle, a forwarded message also carries the trail of the
     nodes it passed;
  2. `event.timer_key`;
  3. an instance ends on the definition it was born with;
  4. at-least-once replay;
  5. a `$ref` to a missing field fails, with an explicit default;
  6. only the admin and the hive's SY.wf-rules may use the WF's controls, and only SY.timer may
     fire its timers. The operator left it as an open security topic;
  7. `target_ref` goes: a new route is a CEL change with fixed names.
- **0.1.89:**
  - the weekly API limit stopped both fix agents halfway; they resumed with their work intact;
  - CI was green on both workspaces, then the build, the deploy and the gate on `AI.pruebas`
    (ledger).
  - The model's one slip was in arithmetic, not in its input: 245 for 305, when asked for only
    the number.
- **What the release itself taught (A-122):**
  - a base runtime published by hand keeps `current` through a package upgrade, and only a manual
    delete hands it back;
  - the 0.1.88 entry's advice, to delete the gate's version after this release, was backwards.
