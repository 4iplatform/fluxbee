## What came out of using the tool for real

- **`ops build`:** with `cd && pull && nohup … &`, the shell sent the whole list to the background,
  pull included. If the pull failed there was no log, and `--wait` waited forever. Now the pull runs
  in the foreground with `set -e`, and the wait aborts if the log does not exist. I tested
  it on fb-build with a fake build, on the good path and with a pull that fails.
- **Live output:** Python buffers stdout when it does not write to a terminal, so the background
  deploy showed nothing until it finished. Now it goes line by line.
- **`health`:** a journal that cannot be read is reported and never counts as zero. The window is
  given in full UTC, because `journalctl` reads a bare time in the VM's time zone.
- **A-31 (new):** the services write ANSI color codes into the journal. My first error count after
  the deploy gave a false 0, because `grep ' WARN '` does not see `\x1b[33m WARN`. Once the codes
  were stripped, the real WARNs showed up: reconnections from the restart, and the already known
  ones. The `ops health` patterns are message text and are not affected (I checked them against the
  router code).
- **Identity during the upgrade:** the worker1 replica retried for 100 s (10:25:21–10:27:03 UTC)
  while the motherbee identity restarted: it waited for the vault and ran the migrations. Then it
  caught up by itself. This is the expected behavior.

### SY.frontdesk.gov against the documents (A-37, detail)

R = `nodes/gov/ai-frontdesk-gov/src/bin/ai_node_runner.rs`, I = `src/bin/sy_identity.rs` (line
numbers as of 2026-10-02).

- **G1, conversational registration:**
  - The prompt does not pass a tenant. The fallbacks (`effective_config.tenant_id`,
    `GOV_IDENTITY_TENANT_ID`) are always empty in production, so it ends in `missing_tenant_id`.
  - Spec §4.2 and identity §6.2: the tenant the case already has is kept.
  - Proposal:
    - the runner takes the tenant from the temporary ILK (identity SHM), which IO creates under its
      own tenant;
    - it accepts `handoff.tenant_id` only if it matches;
    - it removes `tenant_id`/`tenant_hint` from the LLM schema.
  - **Decision:** what to do with the temporary ones that land in the default tenant.
- **G2, new tenants:**
  - Today `TNT_CREATE {name: hint, status:"active"}` skips the approval.
  - Since identity looks up existing tenants by name or domain, someone can join one that is not
    theirs.
  - SY.identity accepts `pending`, and `TNT_APPROVE` belongs to SY.admin only.
  - Proposal:
    - create only on an explicit request for a new organization, as `pending`;
    - do not register into a tenant that was not created;
    - in identity, force `pending` and do not look up by name when the frontdesk creates it.
- **G3, merge by email:**
  - `ILK_ADD_CHANNEL` with `merge_from_ilk_id` is missing.
  - The frontdesk has no way to look up an ILK by email: `ILK_GET`/`ILK_LIST` are admin-only and
    the SHM has no emails.
  - **Prerequisite decision:** proof that the person owns the email, for example a one-time code.
    Without it, anyone takes over someone else's identity.
- **G4:** the vocabulary (§8.1) was superseded by addendum §2.4; the docs still need fixing.
- **G5:** spec §11 describes the old config model, and there are two §11s.
- **G6:** the §12 counters are missing.
- **G7:** a failed handoff does not save its tenant, so the retry without `tenant_id` fails.
- **G8:** the prompt's "no loop" rule turns a transient error into a terminal one.
- **Contradictions between the documents:**
  - spec §3 vs identity §3.1/§6.4: inventing tenants;
  - spec §4.2 vs identity §6.2: the domain match;
  - the spec omits `IN_CONVERSATION`;
  - identity lists errors that are never emitted and omits others that are.
