# 2026-10-26 — Agent tools: a real agent publishes, the tools declared once (0.1.86)

Where the track stands is in [agent-tools-v1](../../docs/agent-tools-v1.md). The facts of the
release are in the ledger's [0.1.86 entry](../DEPLOYMENTS.md), deployed early on 2026-10-27
(ART). This page tells how it went.

## How it went

- **The test tools:**
  - The operator sent an OpenAI key, then a Claude key, for a test tenant, `pruebas`. Both are
    stored only in its vault.
  - A real agent, `AI.pruebas@worker1`, wrote its own HTML page and published it as an artifact.
  - On its first try it answered "unconfigured", because an agent without a role uses the default
    prompt. With a role, it published in 19 s.
  - **The operator's rule:** the test tools stay in the infra. Only what a gate creates is cleaned
    up.
- **"Capabilities," reviewed at the operator's request:** six meanings, none of them what an agent
  can do (A-94). The operator: *"un quilombo… hay que ordenar eso también"*.
- **The conversation** settled agent-tools-v1:
  - two families of tools;
  - one card per tool in the code, and from it the model's definition, a catalog and a HELP;
  - every agent loads every base tool;
  - roles stay reusable;
  - the AI provider per node (A-93);
  - "tools" is the AI node's one word;
  - the frontdesk keeps its own tools.

  The operator: *"cerrá esto de tools y detalles, desorden de AI… arrancá"*.
- **Build:**
  - two agents, one for the AI runtime and one for the HELP path and Archi;
  - then one review round (security, operations), and two agents for the fixes.
- **What the review caught** (A-105):
  - Any node could reconfigure an AI agent, through a `msg_type` the router does not gate. The
    probe saw it on 0.1.85 before the deploy and saw it refused after.
  - Five tool descriptions were longer than OpenAI accepts. That would have broken exactly the new
    per-node provider.
- **The gate:**
  - `AI.pruebas` published on Claude, then on gpt-5.5 after one `config-set`;
  - `llm_usage` showed both charged to the tenant, and the prompt caches working;
  - the agent went back to the hive's provider.

## Lessons

- **The agents' builds were slow.** Two worktrees built the whole dependency tree at once, and
  macOS's code-signing scans (syspolicyd, XProtect) stalled each new binary: up to 102 minutes.
  The agents that built in the shared `target/` were faster.
- **`send_node_message` is fire-and-forget.** An agent's reply is read from SY.storage's `turns`.
  The gate tools in `scratchpad/gate-tools/` do it.
