Cómo funciona

Un mensaje entra. Todo el sistema sabe qué hacer.

Cinco tipos de nodos cooperan dentro de hives locales y entre hives distribuidos.

01
IO

Entra por cualquier canal

Un nodo de entrada convierte cada interacción al protocolo común.

02
RT

Encuentra el destino

El router combina identidad, capacidad y política para decidir la ruta.

03
AI

Un agente resuelve

El agente correcto recibe contexto y herramientas para completar su tarea.

04
WF

El workflow ejecuta

Acciones, validaciones y handoffs avanzan hasta un resultado verificable.

05
SY

El sistema mantiene control

Identidad, memoria, configuración y auditoría permanecen disponibles.

01

Identidad persistente

Cada humano, agente y tenant tiene una ILK que lo acompaña por toda la red.

ilk:550e8400-e29b…
02

Routing por capacidad

Los mensajes llegan a quien puede resolverlos, no sólo a una dirección fija.

requires: support.billing
03

Políticas verificables

OPA separa las reglas de acceso y routing de la lógica de cada agente.

policy: allow + target
04

Local y distribuido

Memoria compartida dentro de un hive; replicación y gateways entre hives.

Probalo localmente

Una malla real, en dos comandos.

El lab levanta motherbee y un worker en Docker usando el mismo instalador y ciclo de servicios del sistema real.

fluxbee / quickstart
# 1. Clone the repository
git clone https://github.com/4iplatform/fluxbee.git
cd fluxbee

# 2. Start motherbee + worker
docker compose -f lab/docker-compose.yml pull
docker compose -f lab/docker-compose.yml up -d

# 3. Ask the control plane what is alive
curl -s localhost:8080/hives | jq .

Antes de empezar

Extendé Fluxbee

Creá una nueva unidad de trabajo.

Empezá con una configuración, un workflow o tu propio runtime. El empaquetado mantiene código, prompts, assets y defaults como una unidad versionada.

config_onlyRecomendado para empezar

Una nueva persona de agente

Prompt, modelo y parámetros sobre un runtime existente. No requiere compilar.

workflow

Un proceso coordinado

Pasos, timeout y escalación sobre el motor de workflows.

full_runtime

Un nodo completamente propio

Tu binario en Rust, Go u otro lenguaje, ejecutado como proceso independiente.

01

Scaffold

fluxbee-scaffold --name ai.soporte.billing
--type config_only --base ai.generic
02

Personalizá

Editá el prompt y los defaults generados en el directorio del paquete.

03

Empaquetá

fluxbee-scaffold pack ./ai.soporte.billing
04

Publicá y ejecutá

Publicalo desde Archi o la CLI, sincronizalo a un hive y creá el nodo.
